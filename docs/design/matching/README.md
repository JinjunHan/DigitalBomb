来源 `docs/design/07-matching.png`，941×1672；所有矩形为左上原点 `[left, top, right, bottom]`。脚本 `scripts/slice-matching.py`，输出 `assets/resources/art/matching/`。

|0|已有 scene|持续书房背景|
|1|opponent|完整未知玩家圆形座位|

原 RGB 裁切加 4 倍抗锯齿蒙版，不重生成完整控件。底座遮挡区域与计时牌、昵称示例文字使用同图纹理补片，属于确定性修补，不是无损提取。玻璃内原沙堆移入独立图层，保留玻璃外轮廓与反光。动画以匹配会话时间采样，排队同步和素材刷新不会从头播放；每周期流沙后翻转半圈，取消/匹配成功退出页面即停止，关闭动效静止显示但计时继续。

## 接入与验证

`GameApp.matchingArtwork` 按同一比例缩放控件与位置，保留安全区；计时器使用服务器 `queuedAt` 实际排队时长，昵称为真实玩家数据。沙漏循环由 `shared/matching-hourglass.ts` 的会话时间函数采样：4.1 秒转移沙量、0.7 秒平滑翻转半圈，翻转期间停止流沙，下一周期反向转移。每次 UI 重绘按同一排队起点恢复当前姿态，不创建重复循环 Tween；匹配成功/取消时清理节点引用。动效关闭时静止显示，排队计时照常更新。

匹配页专用 `SceneCamera` 视角改为 zoom=1.8、lift=.12，使共用桌面上移到金色标题后方，保持从大厅进入与返回的连续视差。没有修改服务端匹配和电脑候补规则。

头像框被示例人物遮住的部分复用现有 `profile/portrait-frame.png`，叶饰来自本稿独立提取；不是将示例头像保存在普通头像框里。底座修补取自本图 `[620,800,640,815]` 的干净深色金属区域；不是生成式重建。切图检查见 dark-sheet.jpg / light-sheet.jpg。

验证：
- `npm test` 27/27（新增沙量转移、翻转边界连续性、关闭动效及异常时钟边界测试）；服务端与客户端类型检查通过。
- 本地真实队列：匹配等待、排队时间递增、候补对手进入准备页、取消匹配返回大厅均通过；沙漏不残留到准备页。
- Web 470×836 设计稿比例和 375×600 短屏均可完整显示、点击取消；长昵称在名称牌内缩小。
- `docs/verification/matching-artwork.png` 为最终实测，`matching-short.png` 为短屏；`matching-hourglass.gif` 是约 4 秒实际连续帧录制片段（含流沙与一次翻转，GIF 回到开头属于片段循环，非游戏动画重置）。
- Web 与 `npm run build:wechat` 成功，导出 `build/wechatgame/`；主包 1920.7 KB，resources 分包 21256.4 KB，现有脚本的主包检查通过。
