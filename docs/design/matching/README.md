## 接入与验证

`GameApp.matchingArtwork` 按同一比例缩放控件与位置，保留安全区；计时器使用服务器 `queuedAt` 实际排队时长，昵称为真实玩家数据。沙漏循环由 `shared/matching-hourglass.ts` 的会话时间函数采样：前 8 帧各 500ms 显示流沙变化，后 8 帧各 100ms 显示翻转，总周期 4.8 秒。沙子的倾斜和沉降已包含在美术帧中；不再使用节点整体旋转、沙堆缩放或原生粒子。通过 `scripts/pack-hourglass.py` 统一画布和中心，保留 RGBA。每次 UI 重绘按同一排队起点恢复当前姿态，不创建重复循环 Tween；匹配成功/取消时清理节点引用。动效关闭时静止显示，排队计时照常更新。

匹配页专用 `SceneCamera` 视角改为 zoom=1.8、lift=.12，使共用桌面上移到金色标题后方，保持从大厅进入与返回的连续视差。没有修改服务端匹配和电脑候补规则。

头像框被示例人物遮住的部分复用现有 `profile/portrait-frame.png`，叶饰来自本稿独立提取；不是将示例头像保存在普通头像框里。底座修补取自本图 `[620,800,640,815]` 的干净深色金属区域；不是生成式重建。切图检查见 dark-sheet.jpg / light-sheet.jpg。

验证（精灵帧版本）：
- `npm test` 27/27；覆盖不同播放节奏、循环边界、长时排队、关闭动效与异常时钟。服务端与客户端类型检查通过。
- 470×836 Web 实际排队录制，检查流沙、翻转、循环回到直立、真实计时及自动匹配后退出动画，快速取消返回大厅通过；浏览器无 warning/error。
- `docs/verification/matching-sprites.png` 为实测截图；`matching-sprites.gif` 为约 5 秒真实连续帧录制，包含翻转与下一循环。GIF 回到开头是录制片段循环。
- `hourglass-sprites/preview.gif` 是素材序列预览，不是游戏录屏；dark.jpg / light.jpg 是透明边缘检查图。
- 生成帧是风格化美术动画，不是物理仿真。第一版翻转起点沙量突变，第二版已针对该问题重新生成。
- Web 与微信导出成功，`build/wechatgame/` 主包 1920.1 KB，resources 分包 22961.3 KB；现有脚本的主包检查通过。
- 未执行微信开发者工具/真机验证，未上传或正式发布。

## 第二轮细化

相机 lift 调整为 .16，并由 `sceneTableScale` 自动补足桌面下沿覆盖。匹配头像增加纸纹背景回退，长昵称截断保持可读。沙漏打包保留原 RGB，在 alpha≥48 的主体周围保留 6px 柔和边缘，移除生成帧空白区域的极淡矩形 alpha，避免背景变暗后出现方形色块。动画帧数和会话时间采样保持不变。

底座中央原有的模糊矩形补片由 imagegen 参考重建为连续金属圆盘，前侧计时牌保留为空，外侧为真实透明轮廓。原始生成图与完整提示词见 `base-reconstruction/`，运行素材由 `scripts/pack-matching-base.py` 等比打包到既有 657×306 画布。若重新运行旧 `slice-matching.py`，需随后执行该打包脚本，避免回到旧矩形修补。匹配与对局头像增加椭圆 Mask，防止方形头像素材从圆框四角露出。
