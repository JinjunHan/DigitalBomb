# 状态反馈设计缺项核查

核查日期：2026-10-28。范围：GameApp.ts、Connection.ts、Platform.ts、server/game.ts、server/service.ts，以及现有页面和 11 张弹窗稿。仅审计，不修改客户端。

## 超时不能共用同一结果语义

| 状态 | 当前实现 | 设计缺项与建议 |
| --- | --- | --- |
| 普通回合第一次超时 | 服务端记一条 digits/hits 为 null 的历史，切换行动方；客户端记录显示“本次超时”，没有专属弹窗 | 非阻断短提示“本次行动超时，已轮到对手”；提醒本人连续两次行动超时会判负，不能遮挡后续操作 |
| 连续两次行动超时 | reason=timeout，进入 finished；旧 feedback 面板显示胜利/再接再厉及原因，再显示结果页 | 超时胜负反馈稿：根据超时方切换“你已超时/对方超时”，不可双方都显示失败 |
| 后手补猜超时 | reason=reply_timeout，先手获胜 | 复用超时结算框，更换原因“补猜时间已结束”；这不是连续两次超时 |
| 准备超时 | reason=prepare_timeout，进入 cancelled，仅展示旧结果页 | 中性取消稿：“准备超时，本局不计胜负”，不能显示失败或揭示未完成的底牌 |
| 好友房过期 | 等待 10 分钟后 reason=room_expired，cancelled | 中性结束稿：“房间已过期”；返回大厅或后续实现重新建房入口 |
| 请求确认超时 | Connection.command 等待 12 秒后提示“确认超时，请查看同步后的状态” | 通用同步状态提示，不可把它当成行动超时或直接判定提交失败，不应鼓励盲目重复提交 |

用户所说的“超时弹窗”尚无截图或原文，无法唯一确认是哪一种；代码可以确认超时终局 feedback 仍为旧代码绘制样式。

## 其他缺项

1. **猜测反馈面板（优先）**：正在验证、0/1/2/3 位命中、4 位命中等待补猜，仍由 feedback() 绘制深色方框。需一套共用美术底板和状态变体，不标出具体正确位置。
2. **结算短反馈（优先）**：胜利、再接再厉、平局仍使用旧 feedback()；应与完整结果页分别定义，避免接连遮挡。
3. **完整结算页变体（优先）**：06-result.png 仅提供胜利稿，result() 尚为通用文字和按钮布局；失败、同轮破解平局、20 轮平局、取消/不计胜负缺设计变体。胜利稿属于“已有稿待接入”，不能算完全缺稿。
4. **其他取消原因**：player_left、both_offline 共用中性取消模板，分别展示“玩家离开，本局已取消”“双方掉线，本局不计胜负”。好友房客人准备时离开可能让房主回到等待，不应强制套取消页。
5. **断线判定结束**：disconnect 与 11-reconnect.png 的“正在重连”不同；终局应复用胜负结算模板并替换原因。
6. **回合提示条**：轮到你、最后一次补猜仍走 turnCue()，需要统一的小条幅设计，而非新增阻断弹窗。
7. **通用轻提示**：口令无效/房间不可加入、频繁尝试、昵称校验、复制口令、回合变化、请求错误等仍复用底部代码绘制 toast；设计一套成功/提醒/错误提示条即可，不需每条消息单独生成整屏图。现有接口把房满等情况合并为“房间暂不可加入”，不能在视觉稿里假设已经有更精确错误码。
8. **再战状态**：等待对方同意、对方已离开、邀请过期缺状态稿。当前等待是按钮文案，后两者是 toast；可作为结算页状态变体，不一定增加弹窗。
9. **记录空态和超时行**：现有记录稿为有数据状态；代码支持空记录和超时行，但缺对应美术状态示例。
10. **初次连接与素材异常**：已有重连稿只覆盖有会话后的断线；初次登录失败、弹窗素材加载中/失败仍缺统一状态规范。素材失败时必须保留不依赖失败素材的可用回退。

## 建议下一批出稿

以共用组件减少重复：①普通超时短提示；②超时胜负反馈；③取消/过期中性面板；④猜测验证和命中反馈状态组；⑤失败/平局结果页；⑥通用 toast 与回合提示条；⑦再战和记录空态状态组。随后统一接入现有状态机，避免增加不必要的点击确认。
