## 分层与动态内容

- 背景复用现有场景，通过独立遮罩压暗；生成稿背景仅供构图参考。
- 纸张、框体、固定按钮按完整美术控件提取；不要把整张稿作为游戏界面。
- 数字、倒计时、记录行、玩家标签计数、设置开关状态均为动态节点，示例数据不能烘焙进底板。
- 记录仅展示命中数量，不提示具体正确位置。示例底牌和数字仅用于设计说明。
- 关闭入口位于弹窗左侧或底部；屏幕右上方保留微信胶囊安全区。
- 最终规则文字以实际代码为准；长文本、空记录、超时记录及短屏排版在接入阶段验证。

## 素材复现

- 原图来源：本目录 11 张 imagegen 设计稿；原始生成提示词见 `prompts.json`，本次没有重新生成按钮。
- 清单：`slices.json` 逐项记录源文件、LTRB 源像素矩形、轮廓蒙版、纹理修补区域、用途和编码方式。所有原稿为 941 × 1672。
- 工具：安装 `pillow`、`imagequant` 后执行 `python scripts/slice-modals.py`。脚本只写本批弹窗素材、清单和 `assets/scripts/shared/modal-art.ts`，已有 `.meta` UUID 保留。
- 固定标题、插画、说明合并为静态框体；完整按钮独立切出。开关、底牌数字、记录标签数量、倒计时、记录行与滑块是独立动态层。
- 控件移除位置、示例数字、示例记录用同稿干净纸纹修补；被前景植物遮挡的边缘用对称边缘修补。记录区使用镜像拼接纸纹，避免拉伸成竖条。这些区域属于纹理修补，并非无损裁切。
- 输出用 libimagequant（最低质量 85 / 目标质量 95、256 色、alpha 感知抖动）控制微信包体；原始全色设计稿保留。最终 PNG 并非逐像素无损副本。
- `dark-sheet.jpg`、`light-sheet.jpg` 是输出素材的透明边缘检查图。运行时复用现有场景与半透明遮罩，不使用生成稿整屏背景。

## 客户端行为

`GameApp.ts` 按统一源坐标整体缩放弹窗、文字与点击区域，并避开安全区。素材整批就绪后展示，失败时显示加载失败和返回入口。

- 设置沿用原有本地存储和声音控制；切换状态不重复烘焙文字。
- 五种确认使用 `shared/modal-state.ts` 校验房间、阶段及回合。锁定/重复猜测展示和提交的是打开时捕获的数字，即使底层草稿发生变化也不替换提交值。
- 记录保留双方标签、真实数量、超时行、空态、ScrollView 滚动位置、回到最新和动态滑块；局内计时继续，结束后切到本局记录。
- 断线弹窗阻断底层触摸，保留自动重连；手动重新连接会关闭旧连接后重新认证，不暂停服务器计时。

## 转场动画

11 类弹窗现有各自的入场、退场和内容错峰方案，详情与实录见 [逐项转场设计](motion.md)。重绘保留进度，遵循动效开关，转场期间阻挡重复输入。
