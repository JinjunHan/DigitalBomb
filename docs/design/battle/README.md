# 准备页与对局页切图接入

来源：`../04-preparation.png`、`../05-gameplay-v2.png`。匹配页复用 `../matching/slices.json` 中已接入的 `07-matching.png` 切图和沙漏序列帧。

- `slices.json`：先记录裁切清单，矩形均为原图 941×1672 的 `[left, top, right, bottom]`。含透明蒙版、多边形轮廓、纹理修补采样区和手牌透视校正四角。
- `../../../scripts/slice-battle.py`：Pillow 确定性裁切、蒙版与同源纹理修补；第二轮新增的空白牌面和两种托盘由内置 imagegen 参考补全。生成原图与提示词保存在 `generated/`，由 `scripts/pack-battle-art.py` 保留 alpha 裁边、等比缩小并打包。补全部分不是无损原图提取。
- 输出：`assets/resources/art/battle/`；`dark.jpg`、`light.jpg` 为深浅背景检查图。
- 静态按钮保留完整图案和固定文字。对手昵称、准备状态、倒计时、回合、手牌、输入和历史记录均来自实时状态，不使用原稿示例值。
- 两页共用现有持久书房背景，保持原有场景过渡。第二轮补齐键盘木托盘，降低远景亮度、提高桌面占比；为保持场景连贯，共用房间仍不是原稿逐像素背景。
- 游戏面板显示最近三条自己的记录，“全部记录”仍打开原有可滚动面板；保留多条历史、超时空值和记录滚动位置功能。
- 每页使用统一坐标与安全区缩放；点击回合牌打开退出确认或游戏菜单；点击底牌可隐藏/查看。

## 验证

运行 `scripts/verify-battle.cjs`（需要 Playwright、Web 构建、本地 preview 和 server）：真实鼠标点击数字、删除、随机、锁定、猜测、记录展开、取消匹配；空记录、超时记录、长昵称、390×693 和 390×600 截图。测试状态只注入浏览器，不增加客户端调试入口。

截图位于 `docs/verification/battle-*.png`。本次为 Web 运行验证及微信本地构建，未做微信开发者工具真机验证或发布。

## 第二轮细化

- 普通牌面无修补接缝、无统一发光边；当前选中牌使用独立原稿金边和轻微抬升。
- 动态数字采用项目内嵌 FriendDigits 粗衬线字体，补齐对局手部、头像框和全部 8 个头像选项的回退。
- 长昵称截断保持字号，点按对手名牌显示完整姓名；按钮透明蒙版按透视倾斜细化。
- 桌面缩放由 `sceneTableScale` 计算覆盖下沿，单测验证所有视角不露空；持续场景不随输入重置。
- 额外点按检查：选中位替换、底牌隐藏/查看、等待/已锁定时禁用输入。记录真实转场帧到 `temp/battle-scene/`；GIF 的帧来自运行截图。
- `battle-comparison.png` 按相同比例排列原稿、第一轮、第二轮，方便继续评估差异。
