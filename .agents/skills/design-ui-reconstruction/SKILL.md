# 设计图分层切图与 UI 还原

本技能来自本项目首页、个人资料、猜测记录和 2.5D 场景的多轮实际迭代。项目路径均相对仓库根目录；先读取当前 `AGENTS.md`，技术栈以工程为准。

## 核心决策

**先分析设计图、分层切图并检查素材，再写界面代码。** 木纹、金属边框、纸张、雕刻字、图标、阴影构成的美术控件，不能靠 Graphics 方框加系统文字代替并宣称完成还原。代码负责节点、布局、实时内容、交互和动画；切图负责设计稿的美术外观。

不是把整张截图当作界面：每个需要独立点击、移动或换状态的元素都应有独立节点。也不要机械地把每个文字和图标拆散；需要整体保真的固定按钮可以作为一张图。

## 开始前：确定版本和范围

- 先看用户指定的图片，再查看当前页面实现和相关素材，不能只根据文件名猜布局。区分最新版、旧名称稿和已批准稿；版本冲突时优先用户当前指定版本。
- 列出本次页面的背景、固定控件、动态内容、状态装饰、动画组。确认哪些内容会变化、哪些图层共用。
- 先生成一个简明素材清单，再切图。清单记录来源、矩形坐标约定、蒙版、输出路径、节点用途、是否包含固定文字、动态区域与绘制顺序。
- 复用已有素材和工具前先检查；本项目旧切图脚本含硬编码坐标，**不要为新页面直接运行它们覆盖现有素材**。

## 分层与切图规则

| 元素 | 处理方式 |
| --- | --- |
| 固定美术按钮 | 整块保留底板、图标、固定文字、箭头和必要阴影；运行时不再叠一遍相同文字 |
| 设置、声音、帮助 | 保留完整图标控件；例如“怎么玩”的问号不能遗漏；状态标记另做一层 |
| 昵称、头像 | 框和内容分开；框内用实际玩家内容，不能烘焙示例姓名或头像 |
| 头像装饰 | 背景 → 动态头像 → 中空头像框 → 选中徽章；徽章不烘焙到普通头像中 |
| 输入框、数字卡牌、倒计时、记录 | 美术底板使用切图，内容由原生组件显示；清除源图示例值 |
| 纸张面板或场景 | 需要暴露被遮挡区域时先补全；按实际动画关系拆层 |

完整提取时尽量保留原 RGB 和原有 alpha。轮廓外透明，保留柔和阴影与抗锯齿；圆角/曲线不要用粗多边形切掉倒角。不要用白/黑色键删除同色的有效细节。头像框需要检查中心确实透明。将素材放在深色、浅色背景上检查是否残留底色、锯齿或硬切边。

区分两条生产路径：

- **原图切图**：适用于已经可见且完整的控件。用户要求切图时，优先使用允许的确定性裁切/蒙版工具，记录坐标以便复现。
- **生成补全/重建**：适用于底图被 UI 遮挡、缺失的框背景、连续场景的隐藏区域。遵循当前可用图像工具与 imagegen 技能要求，保留参考图、提示词和生成原图；说明是重建素材，不称为逐像素无损切图。不要为了方便重新生成已经完整的按钮。

在确认切图轮廓和动态区域正确前，不以原生近似样式继续堆完整页面。视觉替代仅作为明确的资源失败回退，不能当作正常验收效果。

## 接入界面

- 统一设计坐标、锚点、安全区与缩放规则。保持美术控件宽高比，位置和尺寸一起适配；不要只压缩坐标而保持巨大的按钮/文字，造成短屏重叠。
- 独立点击区域覆盖完整控件，静态烘焙文字不重复绘制。禁用、按压、选中状态优先通过独立覆盖层、透明度和轻微缩放实现。
- 持久背景、会话状态与 UI 重绘解耦。异步素材加载、网络同步、输入数字不应重启动画、重置列表位置或销毁正在编辑的输入框。
- 素材批次准备好后再展示完整组合；失败时保留可用回退，避免一半新背景、一半旧前景。
- 保留 Cocos `.meta`，生成文件必须落入项目，不依赖机器私有生成目录。不要为改美术重写服务端规则。

按本次任务需要再读参考，避免每次都执行所有模式：

- 遇到按钮切图、个人资料、输入框偏移或键盘闪退，读 [references/lessons.md](references/lessons.md)。
- 需要纸张插页、返回反推、背景连贯或 2.5D 镜头，读 [references/motion-and-scene.md](references/motion-and-scene.md)。

## 验证与交付

1. 按同一屏幕比例对照设计稿与实际运行截图，依次看构图、元素位置/大小、轮廓、字体、阴影；先修大的布局误差。检查空数据、长昵称、多条记录和不同安全区，不能只验示例静态页面。
2. 实际点按主按钮、返回、取消、保存；有输入则检查焦点保持、键盘及草稿，有列表则检查滚动位置，有动效则录制真实连续帧。看不到动画先检查设置和时间推进，不先归因于微信不支持。
3. 修改客户端后跑 `npm run typecheck:client`。时序/状态逻辑用有意义的边界测试；单纯切图无需编写只匹配文件名或实现文字的测试。Web 只能作为辅助视觉验证。
4. 按根目录 `AGENTS.md` 完成微信导出、包体检查、相关文件提交和推送。构建命令顺序执行，避免争用 Cocos 构建配置。不要纳入无关既有未跟踪文件。
5. 交付素材位置、来源/生成提示词、代码改动、实际截图或动效、验证范围、微信导出目录及 Git 结果。明确区分 Web 验证、微信构建、微信真机验证和正式发布。
