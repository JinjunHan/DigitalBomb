# 转场、状态保持与 2.5D 场景

## 纸张插页：按动画对象分组

用户期望首页到个人资料时背景基本不变，纸张倾斜插入。场景背景留在动画组外，首页内容、资料主体、返回按钮分别成组；返回按钮与纸张从不同方向进入，不能都绑到一张纸上。

本次最终参数用于理解案例，不是所有页面的默认值：

| 对象 | 入场过程 |
| --- | --- |
| 首页内容 | 0–0.5 秒，缩放 1→0.8，透明度 1→0 |
| 资料主体 | 无延迟，从右侧倾斜进入，0.8 秒，缩放 1.2→1，透明度 0.8→1 |
| 返回按钮 | 与主体同时开始，从左进入，透明度 0→1 |
| 共用背景 | 保持原位 |

历史尝试中的首页缩到 0.5、主体延迟 0.3 秒已经被用户修改，不要从旧文档恢复。返回动画按同一时间轴倒放，所以首页在退出开始后的 0.3 秒仍隐藏，然后用 0.5 秒恢复。用 `T - elapsed` 采样统一时间轴，比给所有属性反向设置一个 tween 更可靠。

当前参考：`assets/scripts/shared/profile-transition.ts` 与 `tests/profile-transition.test.ts`。

## “没动画”先定位，不先猜平台不支持

本次用户后来确认界面动效默认关闭。处理顺序：

1. 检查设置及存储值，尊重用户已保存的选择，不偷偷强制开启。
2. 检查触发条件、节点引用、开始/结束位姿和时间轴。
3. 检查构建 UI、加载资源或重绘是否已消耗时间预算、销毁动画节点。
4. 再检查平台差异，有证据才归因于微信限制。

当前资料动画用 `update(dt)` 推进，首帧准备不占完整预算，重绘续接位姿；长帧有上限，切回前台不会直接跳完。动画期间阻挡重复点击和表单编辑。对于未来新页面，保持这些生命周期原则，具体时长由设计决定。

验证真正发生的连续帧，而不只是起点终点两张图。GIF 如用于证据，应由真实运行截图按捕获时间编码，不用重绘帧假装运行结果。

## 共用场景：分层素材比换整张背景更连贯

首页、好友房、匹配与游戏设计看起来是同一房间，但独立生成的图可能存在椅子、道具位置和透视差异。几张整图直接交叉渐变会重影，不能自动得到真实镜头运动。

需要小幅推近、拉远、上下视角变化时，选一张基准场景，统一物件，再拆分：

- 远景：窗户、书架等，补齐被桌面遮挡的区域。
- 桌面：完整桌沿和空桌面，背景透明，移除已拆出的杯子/灯等道具。
- 左右近景：带真实 alpha 的杯子、植物、灯、笔记本。
- 页面 UI：独立于背景，保持字体清晰和点击位置稳定。

当前资源：`assets/resources/art/scene/`；生成来源与提示词：`docs/design/scene-layers/`。这些是参考重建的四层插画，不是原设计文件的原生图层。

`SceneBackdrop.ts` 将场景放在 Interface 同级下方，避免 `render()` 每次重建。`shared/scene-camera.ts` 为大厅、好友房、匹配、游戏定义视角：不同深度层使用不同移动/缩放幅度，切换时插值；快速反向从当前位姿继续。进入个人资料不触发新的背景视角。动效关闭立即到目标。

注意边界与开销：

- 切开的桌面不能带着原房间底色；底图中也不能留下已经独立移动的道具，否则会出现双影。
- 补齐隐藏区域并预留移动余量，测试整个过渡路径、短屏和高屏，防止移动后露空。
- 图片被左右边缘截断的道具，外侧裁切边应一直留在屏幕外，不能推到画面中间暴露直线边。
- 保持前景道具宽高比，交互 UI 位于其上方，前景不接收点击。
- 静止时不反复设置布局；检查纹理尺寸、alpha、资源包体，不把四张完整大背景当作分层方案。

真正需要绕桌、大幅俯仰、看见物体侧面时，2D 视差的能力不足，应说明需要 3D 或混合场景；不要自动扩展成完整三维重建。
